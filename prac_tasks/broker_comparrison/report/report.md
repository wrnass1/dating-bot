## Сравнение RabbitMQ и Redis как брокеров сообщений

### Стенд

- **producer**: генерирует сообщения фиксированного формата и публикует с целевой интенсивностью (RPS).
- **broker**: по очереди `RabbitMQ` и `Redis Streams`.
- **consumer**: читает сообщения, ACK-ает, считает обработанные и latency по timestamp внутри сообщения.

Условия для обоих брокеров одинаковые:

- один и тот же формат сообщения (см. `README.md`)
- одинаковое число producers/consumers
- одинаковая длительность прогонов
- одинаковые лимиты ресурсов брокера (`docker-compose.yml`)

### Метрики

Минимум:

- `throughput_msg_s`
- `latency_ms_mean`
- `latency_ms_p95`
- `sent`, `processed`, `send_errors`, `process_errors`

Дополнительно (можно добавить вручную из UI/cli):

- CPU/RAM брокера
- backlog (RabbitMQ queue depth / Redis stream length & pending)
