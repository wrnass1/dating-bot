# Expected results

Эти выводы получаются при запуске сценариев из `scenarios/` в двух параллельных MySQL-сессиях.

## 1. Dirty read

Начальное значение `accounts.balance` для `Alice` равно `100`.

Сессия `B` меняет баланс на `50`, но не делает `COMMIT`.
Сессия `A` под уровнем `READ UNCOMMITTED` видит `50`.
После `ROLLBACK` в сессии `B` реальное значение снова `100`.

Итог: сессия `A` прочитала данные, которых никогда не было в зафиксированном состоянии БД.

## 2. Non-repeatable read

Сессия `A` в одной транзакции читает баланс `Alice = 100`.
Сессия `B` меняет баланс на `150` и коммитит.
Сессия `A` повторяет тот же `SELECT` в той же транзакции и видит `150`.

Итог: один и тот же запрос внутри одной транзакции вернул разные значения.

## 3. Phantom read

Сессия `A` считает заказы со статусом `new` и получает `1`.
Сессия `B` добавляет новый заказ со статусом `new` и коммитит.
Сессия `A` повторяет тот же запрос и получает `2`.

Итог: в выборке появилась новая строка-призрак.

## 4. Lost update

Обе сессии читают начальный баланс `Alice = 100`.
Сессия `A` записывает `100 + 10 = 110` и коммитит.
Сессия `B` использует свое старое прочитанное значение и записывает `100 + 20 = 120`.

Ожидаемый корректный баланс при последовательном применении двух изменений: `130`.
Фактический баланс: `120`.

Итог: изменение сессии `A` потеряно.
